In brief

rtexjp is an engine that assembles illustrated short vertical videos (reels) in purple, from a script written in a text file (roteiro.json). It’s the engine Nei uses for INEMA reels, open to anyone who wants to study or adapt it: no need to record yourself or pay for an avatar service. It generates the voice, draws each scene frame by frame, mixes the soundtrack, and automatically checks that the video follows the format. You need a computer with a graphics card (GPU), Python, Node, ffmpeg, and two local servers: one for voice (inemavox) and one for images (flux2-klein).

It comes configured with Nei’s voice and avatar. To use your own, replace the voice reference recording (path in VOZ_REF, near the top of rtexjp.py) and the avatar reference photo (path in REF, in motor/gerar_avatar.py), then generate the poses again. These two files are not included in the repository.

What it is

A fixed format, checked by a validator

Every reel follows the same structure: thesis in frame 0, proof with a source, numbered items, an honest caveat, a maxim, and the comment prompt. The engine draws; the validator reports if anything falls outside the format.

🎨 Illustrated, no lip sync

Nei’s illustrated avatar in six poses (arms crossed, hand on chin, pointing, holding, surprised, showing) and a robot mascot. No one needs to record anything.

🎙️ Nei’s voice, local

Voice generated with local TTS (inemavox chatterbox), 160–190 words per minute, with local Whisper marking the time of each word for captions and scene triggers.

✅ Automatic QA

Measures duration, speech pace, volume (−14 LUFS), visual changes per minute, hook word, final card, and silence before the maxim. Produces a qa.md and a contact.jpg.

The format

The nine rules of the rtexjp standard

These are the rules the checar command and QA enforce in every edit.

  1. Thesis written in frame 0, in uppercase, with one word in lilac. It serves as the cover for people scrolling with the sound off.
  2. Proof with a number on screen: a counter lands on the number and the source appears below.
  3. The hook word is the thesis and is introduced early, always in the video’s only warm color (orange).
  4. “N items” with a visible index (01…05) and a pill bar at the top throughout the items.
  5. One item at a time, one object per sentence: the scene’s object changes every 2–3 s.
  1. Every number has a written source on screen (fonte: …).
  2. An honestly spoken caveat, on a warning card (red = problem, green = correct).
  3. A maxim in antithesis, after 0.8 s of real silence (voice and soundtrack stop).
  4. “comment WORD”: the comment box types the word, clicks Publish, and confirms. The card stays for ~9–10 s, with no sign-off.

Quick glossary

Hook word

The word the video asks viewers to comment (here, SETUP). It is the thesis itself, appears early, and is the only thing in orange.

Maxim

The summary line at the end, in antithesis (“Everyone has the model. Almost no one has the setup.”). It comes after a short silence.

Stage

The motor/palco.html page that draws each scene. The renderer takes a snapshot of it for each frame.

Music bed

Quiet soundtrack beneath the voice, which lowers when the voice speaks and stops during the silence before the maxim.

LUFS

A measure of perceived loudness. −14 LUFS is the volume social networks use as their standard.

CTA

“Call to action”: the video’s final prompt. Here there is always just one: “comment WORD”.

TTS and lip sync

TTS is a voice generated from text. Lip sync is the mouth moving along with the speech; rtexjp doesn’t do that—the avatar only changes poses.

Whisper and Playwright

Whisper transcribes the voice and timestamps each word. Playwright opens the stage in a headless browser and takes a snapshot of each frame.

Typographic flash

A quick screen with only large text between items, so the video doesn’t feel static.

How it works

Six steps, one command each

rtexjp.py runs the steps in order. The stage is an HTML page drawn by window.render(t): the same build/cena.json always produces the same video. The voice does not: TTS output varies a little each time (so the voz step lets you redo just a few blocks).

roteiro.json→ checar→ voice + Whisper→ scene→ render (Playwright, 30 fps)→ mix (−14 LUFS)→ QA→ final.mp4
1

Script and validation

checar checks the block order by the tipo field (tese → autoridade → tese → virada → metodo ×2–5 → ressalva → maxima → cta), the number of items, and the hook word.

2

Voice and scene

voz generates one audio file per block, speeds it up to 1.15×, and joins them; cena combines the script with each word’s timing.

3

Render, mix, and QA

render captures the stage frame by frame; mix adds the soundtrack (which stops during the silence before the maxim); qa measures everything.

Prerequisites

What needs to be on your machine

Everything runs locally. No paid APIs are called. The paths below are hard-coded; if your machine differs, adjust them in the files mentioned.

Voice: inemavox + chatterbox environment

Clone the inematds/inemavox project into ~/projetos/inemavox (the engine calls its tts_direct.py and whisper_daemon.py). Chatterbox TTS and Whisper large-v3 run in a separate Python environment (Nei uses the chatterbox conda env in ~/miniconda3/envs/chatterbox); if yours is elsewhere, set the variables below. Whisper large-v3 uses about 10 GB of video memory (NVIDIA GPU), plus chatterbox. Tested on Linux.

git clone https://github.com/inematds/inemavox ~/projetos/inemavox
# install chatterbox and faster-whisper in a dedicated environment (see the inemavox README)
export CHATTERBOX_PYTHON=/caminho/do/env/bin/python3   # TTS
export CS_WHISPER_PY=/caminho/do/env/bin/python3       # Whisper
export CS_INEMAVOX=~/projetos/inemavox                # if cloned elsewhere

Images: flux2-klein

The inematds/inemaimg server running at http://localhost:8000 with the flux2-klein model, plus the avatar reference photo (REF in motor/gerar_avatar.py). Only needed for optional steps 4 and 5 (poses and scene images); Nei’s six poses are already included.

Node, ffmpeg, Python

Node 18 or newer, ffmpeg (with ffprobe, which comes with it), and Python 3 with Pillow and numpy.

git clone https://github.com/inematds/rtexjp
cd rtexjp
npm i
npx playwright install chromium
pip install --user pillow numpy   # or inside a venv
User guide · step by step

From script to final.mp4

Each edit lives in edicoes/<id>/. Steps 3 and 6 through 9 can also run all at once with the tudo shortcut (step 10).

1

Set your voice reference you

The voice step clones a short recording. In the code, it points to Nei’s recording, which is not included in the repository; without changing it, the voz step fails. Record about 10 to 20 seconds of clean speech in WAV format, and change the VOZ_REF path near the top of rtexjp.py. If you’re changing the avatar too, replace REF in motor/gerar_avatar.py with a photo of yourself and run step 4.

grep -n VOZ_REF rtexjp.py          # line to change
grep -n "^REF" motor/gerar_avatar.py   # only if changing the avatar
2

Write the script you

Copy the example script and replace its content. The format is summarized just below the guide in “The roteiro.json file”.

mkdir -p edicoes/minha-edicao
cp edicoes/2026-10-28-5-coisas/roteiro.json edicoes/minha-edicao/   # edit it afterward
3

Validate the format rules

No taste involved, just rules. It rejects: incorrect block order, fewer than 2 or more than 5 items, an index that does not match the number of items, digits or exclamation marks in speech (spell out numbers), a fonte that does not exist in fontes, a word in destaque_fala or a trigger that is not in the speech, an on-screen number without a source, a hook missing from the CTA or not introduced earlier, a hook with an accent or lowercase letters, or silence before the maxim outside 0.5–0.9 s.

python3 rtexjp.py checar edicoes/minha-edicao
4

Avatar poses optional

Nei’s six poses are already in motor/avatar/. Run this only if you replaced the reference photo (REF) with a photo of another character.

python3 motor/gerar_avatar.py
5

Scene images optional

An image using local flux2-klein (default size 1152×784). Today, only the stage’s carro component uses an image (motor/assets/carro.png); a new image needs a component that loads it in motor/palco.html.

python3 motor/gerar_imagem.py motor/assets/x.png "<prompt>"
6

Voice for each block + timing for every word

One audio file per block in Nei’s voice; Whisper marks each word in build/tempos.json. Pass block names to redo only those. If Whisper fails, the log is at ~/.cache/whisper_daemon.log.

python3 rtexjp.py voz edicoes/minha-edicao            # all blocks
python3 rtexjp.py voz edicoes/minha-edicao p2 ressalva  # only these
7

Build the scene and inspect individual frames

cena writes build/cena.json. Before the full render, capture a few frames (in seconds) to inspect.

python3 rtexjp.py cena edicoes/minha-edicao
node motor/render.mjs edicoes/minha-edicao/build --quadros 0,10,20   # -> edicoes/minha-edicao/quadros/
8

Render at 1080×1920, 30 fps

Playwright captures the stage frame by frame, and ffmpeg combines them into build/video.mp4 (no audio).

python3 rtexjp.py render edicoes/minha-edicao
9

Mix and QA

Voice + quiet soundtrack (which stops during the silence before the maxim), final volume at −14 LUFS; then QA writes qa.md, build/qa.json, and contact.jpg. Any failed criterion appears with ❌ in qa.md, and the command ends with a Python error (CalledProcessError): this means QA failed, not that there is a bug.

python3 rtexjp.py mix edicoes/minha-edicao   # -> final.mp4
python3 rtexjp.py qa  edicoes/minha-edicao   # -> qa.md, contact.jpg
10

Or run everything at once

Runs checar → voz → cena → render → mix → qa. Stops if checar fails.

python3 rtexjp.py tudo edicoes/minha-edicao
11

Review before publishing you

Open contact.jpg and watch the video. The CTA promises something to anyone who comments: that material needs to exist before the video goes live. Publication is outside this repository.

The roteiro.json file

The script format, at a glance

An object with id, versao, titulo, isca, fontes, and the blocos list. A shortened excerpt from the real example:

{
  "id": "2026-10-28-5-coisas", "versao": "rtexjp/1",
  "isca": { "palavra": "SETUP", "entregavel": "os 5 links e os comandos..." },
  "fontes": [ { "id": "ecc", "valor": "291 mil estrelas", "linha": "github.com/affaan-m/ECC · 28/10/2026" } ],
  "blocos": [
    { "id": "tese", "tipo": "tese",
      "fala": "Cinco coisas de IA saíram este mês, e quase ninguém percebeu.",
      "tela": { "texto": "5 COISAS DE IA QUE QUASE NINGUÉM VIU", "destaque": "NINGUÉM" },
      "cena": { "comp": "titulo" }, "pose": "queixo", "destaque_fala": ["cinco", "ninguém"] },
    // ... authority, thesis, turn, method ×5, caveat ...
    { "id": "maxima", "tipo": "maxima", "silencio_antes_s": 0.8, "cena": { "comp": "flash" },
      "fala": "O modelo, todo mundo tem. O setup, quase ninguém." },
    { "id": "cta", "tipo": "cta", "hold_s": 6, "cena": { "comp": "cta" }, 
      "fala": "Comenta SETUP que eu te mando os cinco links e os comandos." }
  ]
}

Fields in each block

tipo (order shown above) · fala (spelled out, no digits) · fala_tts (optional, spelling for correct TTS pronunciation) · tela (large text and highlighted word) · cena.comp + cena.params (what the stage draws; params.gatilhos links a scene change to a spoken word) · avatar pose · destaque_fala (colored words in the captions) · fonte (id in fontes) · rotulo and n (item number).

Stage components (cena.comp)

titulo, contador, frase, indice, pasta, repo, carro, mapa, equipe, ressalva, flash, cta. The robot mascot is drawn by the stage itself, next to the avatar, and reacts to the scene (question mark, alert, check mark). Poses: bracos, queixo, apontando, segurando, surpreso, mostrando. The parameters for each component are in the example edicoes/2026-10-28-5-coisas/roteiro.json.
